- Query/filter parameter (JMESPath) for large non-file JSON-returning tools (`get_events`, `get_posts`, `search_all`, `search_files`, `get_groups`) so the agent can project/filter server-side instead of ingesting the full result — same "grep, don't ingest" motivation as the file-resource work below, but a separate, smaller follow-up. No separate shape-documentation mechanism needed (MCP's `outputSchema` already covers response shape); just add 2-3 example JMESPath expressions to each tool's description.
- CLI status command: Check external dependencies (pdftotext, docx2txt) and that the token works. Do not fail on missing items, just show what is working and what is not.
- Review code for clean separation between input/parsing, logic, integration. Hexagonal style.

- `search-files` should also search post attachments, not just the group Files tab. Currently it only calls `getGroupFiles(groupId)` (the shared group file repository) — it misses files attached to individual posts (`post.attachments[]`), which today are only reachable via `get_attachment` if you already know which post they're on. Needs fetching posts (all types, across groups) alongside group files and feeding their attachments through the same filename/content matching pipeline.

Token passthrough via request header (e.g. `Authorization: Bearer <token>`) instead of `SPOND_TOKEN`/token file, since a remote server can't read the caller's local `~/.config/spond/token`. Intended user sequence: (1) `spond-mcli login` locally to obtain/save the token, (2) configure the MCP connection in the agent — the agent needs clear instructions on where that token goes (which config field, which header) when pointing it at the remote HTTP endpoint. **Done**: implemented (`src/http-server.ts`, `src/http-auth.ts`), Dockerfile added, deployed and verified end-to-end against a real deployment over HTTPS with token passthrough working. No server-side persistence needed (auth is stateless per-request via header).

## Completed

- HTTP mode file isolation + context-minimizing content access (2.0.0, breaking change): per-token workspace directories (`os.tmpdir()/spond-mcli-workspaces/<sha256(token)>`, `src/workspace-manager.ts`) isolate concurrent HTTP users' file operations from each other — same token always resolves to the same directory, so it survives across HTTP's stateless-per-request model without any in-memory registry. `get_attachment`/`get_group_file` no longer take a caller-supplied `filePath` (meaningless over HTTP, since that path lands on the remote container, not the client) — they download into the workspace and return an opaque `resourceId`. `convert_pdf_to_text`/`convert_docx_to_text`/`convert_xlsx_to_text` take that `resourceId` instead of `inputPath`/`outputPath`, returning a capped preview + lineCount rather than the full document. New `search_resource_text(resourceId, searchTerm)` tool greps the converted text server-side (case-insensitive substring match) so an agent finds what it needs without ingesting the whole document into context. Unified onto stdio too rather than keeping a dual schema, since this was already breaking. TTL-based sweep (24h default, hourly check, `.unref()`'d) evicts stale workspaces on the HTTP server; stdio uses a per-process `mkdtempSync` dir cleaned on exit. `resolveResourcePath` sanitizes/rejects path-traversal attempts so one HTTP caller can't escape their own workspace. Along the way, fixed a real bug caught during manual end-to-end verification: the `text/` namespace directory was never created before a converter binary wrote into it, so every conversion failed with an I/O error until `fs.mkdir` was added before the `convert()` call — now covered by a regression test using a real minimal PDF through the real `pdftotext` binary. Verified end-to-end against the real API over HTTPS: `get_group_file` → `convert_pdf_to_text` → `search_resource_text` chain against a real PDF group file, correctly isolated between two different bearer tokens. Full design in `/Users/anderssv/.claude/plans/sharded-dancing-popcorn.md`.

- Unified search (`spond-mcli search <term>`, MCP tool `search_all`): Searches across everything at once — events, plain posts, polls, and payment requests — in one call, tagging each result `kind: "event"|"post"`. Along the way: fixed a real bug where the post `type` filter used `PAYMENT_REQUEST`, but the real API's query param is `PAYMENT` (returning items whose actual `type` is `CLUB_PAYMENT`) — `--type PAYMENT_REQUEST` was silently 404ing. `SpondPost` now models `poll` (question, description, options with vote counts) and `clubPayment` (title, amount, status) since polls/payments are posts with that data embedded, not top-level title/body. `createPostSummary` falls back to `poll.question`/`clubPayment.title` when title/body are absent, and surfaces vote counts and payment status/amount. The narrower `search-events`/`search-posts` commands are kept for when you only want one type. Also fixed: the MCP server (`spond-mcli mcp`) only read `SPOND_TOKEN` and never fell back to `~/.config/spond/token` like the CLI does and the README already promised — now it does. Verified end-to-end against the real API (found and correctly enriched a real poll and two real club payments).

- Fix user/pw login (`spond-mcli login`): Replaced the Playwright browser-scraping login as the default with direct email/password authentication, matching the request/response shape documented in the community `spond` Python package (`POST /core/v1/auth2/login` with `{email, password}`, response `{accessToken: {token, expiration}}`). Credentials come from `SPOND_USERNAME`/`SPOND_PASSWORD` or an interactive terminal prompt (password input hidden via a small raw-mode reader in `src/prompt.ts`). Error messages only surface Spond's documented safe diagnostic fields (`error`, `errorKey`, `errorCode`, `message`) — never 2FA challenge tokens or phone numbers. Kept the old Playwright flow available as `spond-mcli login --browser` for accounts with 2FA enabled, since direct email/password login can't complete a 2FA challenge. Verified end-to-end against the real API — no more Chromium dependency for the default login path.

- My members command (`spond-mcli my-members`): Lists memberIds of everyone you're a guardian for, across all groups, with names and group names attached — no need to dig through event details to find the right memberId. Fetches `getGroups()` once, resolves matches via a pure `resolveMyMembers()` domain function, caches the result to `~/.config/spond/members.json` (0600 permissions) with a 5-minute TTL so repeated calls don't hit the API. On refresh, only rewrites the cache (and logs to stderr) if the resolved member list actually changed. Verified end-to-end against the real API.

- Fixed a real bug found while building the above: `SpondClient.getCurrentUserProfileId()` was hardcoded to a fake ID left over from development, instead of calling the real API. It now calls `GET /core/v1/profile` (documented in the community `spond` Python package) and memoizes the result. This also fixes the existing per-event "is my kid accepted/declined" attendance-status enrichment, which silently used the wrong ID for any account other than the original developer's.

- CLI login command: Opens Playwright browser at spond.com/client, polls localStorage for token after user authenticates, and saves it (raw, no decoding — the API rejects a base64-decoded token) to `~/.config/spond/token` with 0600 permissions. Poll loop tolerates the SPA navigating mid-poll (transient `page.evaluate` failures no longer abort login). Verified end-to-end against the real API.
